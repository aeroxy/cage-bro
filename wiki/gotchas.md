# Gotchas

Edge cases, limitations, and things that will bite you.

---

## File Operations Are Sandbox-Scoped

All file paths are resolved relative to a `workspace/` directory created in the current working directory. You **cannot** read `/etc/passwd` or write to `~/.ssh/`. Path traversal attempts (e.g., `../../etc/passwd`) are rejected.

```bash
# This works
curl -X POST http://localhost:8080/v1/file/read -d '{"path": "README.md"}'

# This fails with a path escape error
curl -X POST http://localhost:8080/v1/file/read -d '{"path": "../../etc/passwd"}'
```

**Gotcha**: The workspace is relative to where you started `cage-bro serve`. If you start it from `/home/user/projectA`, file paths are scoped to `/home/user/projectA/workspace/`. Starting from a different directory gives you a different workspace.

---

## `file_edit` Only Replaces the First Occurrence

The edit endpoint uses `replacen(..., 1)` -- it replaces only the **first** match of `old_text` with `new_text`. If the string appears multiple times, only the first one changes.

```bash
# File contains: "foo bar foo baz"
curl -X POST http://localhost:8080/v1/file/edit \
  -d '{"path": "test.txt", "old_text": "foo", "new_text": "qux"}'
# Result: "qux bar foo baz"  -- second "foo" is untouched
```

**Workaround**: For multi-replace, read the file, do the replacement yourself, and write it back with `file_write`.

---

## Stateless Code Execution Has No Shared State

`POST /v1/code/python` and `POST /v1/code/node` spin up a fresh process each time. Variables, imports, and state do not persist between calls.

```bash
# This works within one call
curl -X POST http://localhost:8080/v1/code/python \
  -d '{"code": "x = 42\nprint(x)"}'

# This fails -- x doesn't exist in a new process
curl -X POST http://localhost:8080/v1/code/python \
  -d '{"code": "print(x)"}'
# stderr: NameError: name 'x' is not defined
```

**Fix**: Use Jupyter kernels for stateful execution (`/v1/code/jupyter/start` + `/v1/code/jupyter/execute`).

---

## Browser Requires `cage-bro setup` First

The Obscura headless browser is not bundled. You must run `cage-bro setup` to download it to `.cage-bro/bin/`. Without this, all browser endpoints return errors.

```bash
cage-bro setup
# Downloads obscura binary to .cage-bro/bin/obscura
```

If the local binary isn't found, cage-bro falls back to `obscura` on your PATH.

---

## Browser: One Instance at a Time

The `BrowserManager` manages a single browser instance. Calling `launch` twice without `close` in between will fail or behave unexpectedly. Always close before re-launching.

```bash
# Launch
curl -X POST http://localhost:8080/v1/browser/launch

# ... do stuff ...

# Close before re-launching
curl -X POST http://localhost:8080/v1/browser/close

# Now you can launch again
curl -X POST http://localhost:8080/v1/browser/launch
```

---

## Browser `type` Dispatches Events But May Not Trigger Framework Handlers

The `browser/type` endpoint sets the element's value and dispatches `input` and `change` events via JavaScript. This works for plain HTML forms but may not trigger React/Vue/Angular's synthetic event handlers because the events aren't "trusted" (not generated by real user input).

**Workaround**: Use `browser/evaluate` to dispatch events the framework listens to, or use the CDP `Input.dispatchKeyEvent` directly if you need trusted events.

---

## Browser `click` Uses `querySelector().click()`

The click implementation is `document.querySelector(selector).click()`. If the selector matches nothing, you get a JS error. If it matches a non-interactive element, the click fires but may not do what you expect (no focus, no scroll-into-view).

---

## Jupyter Kernels Are Python-Only (Currently)

The `language` field in `/v1/code/jupyter/start` accepts `"python"` only. Other languages return an error. The kernel uses `ipykernel` which requires Python.

---

## Jupyter `interrupt` Is a No-Op

The `POST /v1/code/jupyter/interrupt` endpoint returns `{"status": "interrupted"}` but does **not** actually send a signal to the kernel process. Long-running code won't be interrupted.

**Workaround**: Shutdown and restart the kernel.

---

## MCP Tools Have Hardcoded Timeouts

`python_exec` and `node_exec` MCP tools have a hardcoded 30-second timeout. The REST API lets you set `timeout_ms` per request, but MCP tools don't expose this parameter.

---

## REST API Always Returns 200

Even on errors, the HTTP status is 200. Errors are indicated by an `"error"` field in the JSON body. Check the response body, not the status code.

```json
// Success
{ "exit_code": 0, "stdout": "hello", "stderr": "", "duration_ms": 10 }

// Error (still HTTP 200)
{ "error": "Failed to parse command: ..." }
```

**SDK behavior**: The Python and TypeScript SDKs throw exceptions when the `error` field is present.

---

## No WebSocket Authentication

The WebSocket terminal endpoint (`/v1/shell/session/{id}/ws`) has no authentication. Anyone who knows the session ID can connect. The session IDs are UUIDs (hard to guess), but this is security by obscurity.

---

## PTY Sessions Don't Survive Server Restart

Session state is in-memory. If cage-bro restarts, all sessions are lost. There's no persistence layer.

---

## `shell_exec` Timeout Behavior

When `timeout_ms` is set, the command is killed after the timeout. However, the timeout applies to the entire command including process startup. Fast commands that spawn long-running children may not be properly timed out if the parent exits quickly.

---

## Search Is Case-Insensitive and Text-Only

`file_search` does case-insensitive substring matching. No regex support. The `file_pattern` parameter is a simple glob (e.g., `*.rs`), not a full regex pattern.

---

## Dashboard Is Embedded at Build Time

The React dashboard is compiled to static files and embedded into the Rust binary via `rust-embed`. Changes to the dashboard require rebuilding the binary. The dashboard has a mock mode that activates when the backend is unreachable, so you can develop the frontend independently with `npm run dev`.
